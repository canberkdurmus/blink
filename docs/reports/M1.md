## Notes for the owner

- **PERF-4 reading (ADR 0011).** "Per file (worker thread)" is read as: the work runs off the UI
  thread, and that worker may fan one JPEG's decode out over all cores. One thread can't reach
  25 ms (zune-jpeg ~70–76 ms; serial Huffman decoding alone ~45–55 ms), so Blink now has its own
  parallel baseline-JPEG decoder (`blink-decode/src/pjpeg.rs`), with zune-jpeg as the fallback.
  It contains one `unsafe` call (AVX2 dispatch after runtime detection), justified in ADR 0011.
  **Please confirm this reading.**
- **PERF-4 numbers.** Ryzen 7 PRO 7840U: ~20 ms median on AC power. This gate's run (below) was
  on **battery** (EPP `balance_power`) and gave 22.6 ms; earlier battery runs in the same session
  gave 20.6–25.1 ms. So on battery the budget is met only just, and once it was missed by 0.1 ms.
  The CI Linux runner (fewer cores) measures ~66 ms. That number is a regression baseline, not a
  budget check.
- **Headless split (ADR 0010).** The GUI entry points for OPEN-1 (drop, dialog, `blink [folder]`)
  ship with VIEW-1 in M2. On-disk sidecar writes for OPEN-2 pairs, and the CLI `rate`/`label` without
  `--dry-run`, ship with FILE-4 in M3.
- **CI failure in the table.** Run 44588677164 failed "Perf compare (Linux)" on a docs-only commit:
  PERF-4 median 150.7 ms vs baseline 117.9 ms (+27.8%), with all 5 runs uniformly at 149.9–152.2 ms.
  That's runner-host variance, not a regression; earlier runs on the same code measured 114.7–114.8 ms.
- **Tooling fix during the gate:** `cargo xtask bench` now writes `target/bench/results.md`, so this
  report includes raw runs (#11).
